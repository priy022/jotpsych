Who to reach out to, grouped by how long it's been

"How long it's been" counts days since we last actually heard from them — a reply resets the clock. If they've never replied, it's simply days since they went quiet. Two months (60 days) of silence is the point where we treat it as urgent.

What's actually working

Every reply gets scored, and we watch which type of message earns the best responses for each kind of clinician — the machine leans toward that type next time, without ever fully ruling the others out.

Held back this cycle

Before anything goes out, it's checked against what we know about that clinician — like a contract that hasn't ended yet. If a message doesn't clear that check, we send something safer instead and log why.

What's real vs. simulated in this prototype
Actually running: sorting by how long someone's been quiet, scoring replies to tell warm from cold, choosing what to send next based on what's worked before, the check that stops a sales-flavored message from reaching someone locked into a contract, and the reassessment check that watches whether reply rates are holding up overall.

Simulated, clearly marked: new data arriving (the month buttons stand in for a file landing automatically); actually sending the message (logged here, not transmitted); and logging a reply (in production, a simple form does this — what you're seeing is what that form would produce). The reference code next to each entry is real — it's how a reply gets traced back to the exact message that prompted it.
